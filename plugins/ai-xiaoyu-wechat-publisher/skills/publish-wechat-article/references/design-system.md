# 公众号发布视觉与兼容规范

## 默认方向

采用蓝白结构主义信息版：高信息密度、明确层级、编辑感强、少装饰。视觉重心来自大标题、编号、规则线、色块和留白，而不是 AI 插画或发光渐变。

## 色彩

- 主蓝：`#0759ed`
- 深蓝：`#063ca8`
- 黑：`#080b11`
- 正文：`#202632`
- 次级文字：`#667085`
- 浅蓝背景：`#eef5ff`
- 页面底色：`#fbfdff`
- 白：`#ffffff`
- 分隔线：`#dbe7fb`

仅在强调关键词、章节编号和提示卡中使用主蓝。正文保持黑灰，避免整段蓝字。

## 字体

优先使用系统中文字体栈，避免公众号编辑器丢失外链字体：

`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`

- 封面主标题：黑体感，字重 800–900。
- 正文章节标题：字重 750–850。
- 正文：16–17 px，行高 1.8–1.95。
- 英文标签：全大写，小字号，适当字间距。

## 文章版式

- 正文最大视觉宽度：760 px 左右。
- 移动端必须单栏，无横向滚动。
- H2 使用自动章节编号，源文字中的 `01`、`1.` 等前缀应先去除，避免重复。
- 段落之间保持清晰节奏；连续长段应拆分。
- 关键结论使用蓝色边框提示块或大号引语。
- 表格在移动端允许单元格合理换行，不依赖横向滚动。
- Prompt/模板内容使用浅蓝卡片、清晰标题和可复制文本，避免黑色终端代码风。
- 不为了“丰富”加入无信息价值的图标、emoji 或渐变光效。

## 复制兼容规则

微信编辑器可能移除 `<style>`、类名和脚本，因此：

- `#copy-area` 内所有视觉样式必须写入元素的 `style` 属性。
- 不把 `<script>`、按钮、提示条或浏览器控件放入 `#copy-area`。
- 不依赖 CSS 变量、媒体查询、伪元素或外部字体维持核心排版。
- 复制时同时写入 `text/html` 和 `text/plain`。
- 保持 H1/H2/H3、p、blockquote、ol/ul、table 等语义标签。
- 微信粘贴后仍需人工检查图片宽度、表格换行和段前段后距。

## 横版封面

- 逻辑画布：900×383。
- 导出：1800×766 PNG。
- 安全区：四周至少 28 px；右下角和边缘避免放关键小字。
- 主标题建议两行，首屏可在 1 秒内读完。
- 强调词只选一个，例如 `AI`、`Skill`、`定位`。
- 副标题回答“用户会得到什么”，不重复主标题。
- 侧栏标签和序号只作为秩序元素，不抢主标题。
- 禁止文字贴边、被裁切、字距异常或中英文引号混乱。

## 内容边界

本 Skill 负责发布设计和格式转换，不默认改写事实、扩写观点或联网核实内容。需要编辑或事实核查时，先完成文章内容，再进入本流程。

## 支持的 Markdown

稳定支持：

- H1–H3
- 普通段落
- 有序/无序列表
- 引用
- Markdown 表格
- 围栏代码块（转成 Prompt 卡片）
- 加粗与行内代码

复杂嵌套 HTML、脚注、数学公式和交互组件应先改写为公众号可承载的静态内容。
